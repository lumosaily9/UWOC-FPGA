# 调试经验与工程技能包

## 1. 从时钟和状态机确认串行协议

**观察。** 串行IP名中含有uart，但发送移位寄存器为8位，位计数到7后装入下一字节，帧前另有44位同步段。

**提炼。** 协议以移位寄存器位宽、位计数终值和帧状态转换为准。串行链路按连续8位字节组织，不套用每字节8N1的速率折算。

**验证。** 串行测试逐位比较同步段和255字节码字，同时检查200 MHz时钟下每位保持10周期。帧末测试采用最高位为1的末字节，检查最后一位是否完整输出。

**边界。** 本规则用于本工程的自定义光链路串行口。115200 bit/s统计串口使用其独立发送逻辑。

## 2. 帧长决定计数器边界

**观察。** RS编码每239字节信息生成255字节码字。译码器保留校验区输出，后级提取前239字节。

**提炼。** 译码输入使用255字节边界，业务输出使用239字节边界，两个TLAST分别对应不同的数据单元。

**验证。** 帧裁取测试检查有效信息的数量、顺序、最后一字节TLAST及后续16字节的处理。对输入间断与后级反压分别施加激励。

**边界。** 改变RS参数时，ROM深度、帧计数、TLAST位置和PS信息长度一同调整。

## 3. 计数器必须容纳最大值

**观察。** 单字节可能出现8个错误比特，3位计数器只能表示0至7。

**提炼。** 取值范围包含上限时，位宽满足`ceil(log2(max_value + 1))`。单字节错误数使用4位，每帧错误数覆盖239×8个比特。

**验证。** 分别输入无错、单比特错误和8比特全错字节，再检查239字节整帧累计。

**边界。** 统计结果位于RS译码后的信息支路，改变统计位置时重新确定参考序列及总比特数。

## 4. 流接口只在握手时推进

**观察。** 后级TREADY拉低时，数据源仍可能保持TVALID。仅按输入有效推进计数会跳过尚未交付的数据。

**提炼。** 输入消费使用输入的有效与就绪同时成立条件。输出在有效且后级未就绪时保持TDATA、TLAST及TVALID。

**验证。** 帧整理测试包含连续输出、输入间断、随机反压和帧边界停顿，逐字节核对恢复顺序。

**边界。** 本规则解决可反压字节流的交接。持续到达、不可暂停的物理输入还需要匹配FIFO容量及吞吐预算。

## 5. 将DMA任务和网络发送分开

**观察。** 原有程序在启动DMA失败后也置忙标志，UDP函数还固定使用239字节而忽略调用长度。

**提炼。** DMA成功启动后才进入等待完成状态，错误中断与复位释放调度状态。UDP发送长度使用函数参数，信息帧调用保留239字节。

**验证。** PS测试覆盖启动失败、错误恢复、完成中断、缓存操作顺序与UDP长度。接收工具用本地UDP回环检查数据保存及统计文件。

**边界。** SDK驱动和板级网络配置由Vitis平台生成。复现时使用对应XSA生成的驱动、地址与中断号。

## 6. 将幅度域扩展作为独立模块验证

**观察。** 幅度域扩展处理12位样值，主串行工程处理已经恢复的单比特电平，两者接口不同。

**提炼。** 主链路与幅度域扩展分别组织源码、测试入口及结果。扩展模块以120 MSa/s和每码元6点的配置检验选相与FFE定点运算。

**验证。** 扩展回归逐项检查4096项FFE整数结果、正负饱和、反压保持、FIFO溢出恢复和收发窗口互斥。

**边界。** 扩展模块接入整机时，需要连接实际采样接口、系数装载及帧处理，接口时钟与复位沿相应数据通路组织。

## 复用入口

- `python build/run_sim.py`：串行和字节流主链路模块。
- `python build/run_extension_sim.py`：幅度域及半双工扩展模块。
- `python build/check_sources.py`：Vivado工程引用和速率配置。
- `python build/check_package.py`：包结构、文件命名及Python语法。

验证结果保存在`sim/results/`与`build/results/`。对工程修改后重新执行对应入口，生成对应版本的结果。
